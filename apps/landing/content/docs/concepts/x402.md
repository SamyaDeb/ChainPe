title: x402
description: How an HTTP API asks for a payment, and how an agent answers.
---

x402 is an open standard that uses the HTTP status `402 Payment Required` to ask for a payment. ChainPe uses x402 version 2.

## A paid call

1. The buyer sends a normal request, with no payment.
2. The proxy answers `402` with a `PAYMENT-REQUIRED` header. It lists the price, the wallet to pay and the ways to pay.
3. The buyer signs a USDC payment and sends the request again with a `PAYMENT-SIGNATURE` header.
4. The proxy sends the signed payment to Circle to settle.
5. Once it settles, the proxy forwards the request to your API.
6. The buyer gets your API's answer, with a `PAYMENT-RESPONSE` header holding the transaction hash or Gateway payment id.

Your API never sees the payment headers. It never receives a request whose payment is pending or failed.

## Networks

Payment options name their network in CAIP-2 format: `eip155:5042002` for Arc testnet and `eip155:5042` for Arc mainnet. All values are in [networks and addresses](/docs/reference/networks).

## Discovery documents

`chainpe doctor` generates these, and the proxy serves them for free:

| Path | What it holds |
|---|---|
| `/.well-known/x402` | Your resources, prices, networks and payment options |
| `/openapi.json` | Your paid routes, with parameters and response fields |
| `/.well-known/agent.json` | The agent card your ERC-8004 identity points to |

The proxy answers these itself, and never forwards them to your API.
