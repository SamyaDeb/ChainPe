---
title: x402 protocol
description: The exact requests, headers and payloads of a paid call.
---

x402 is an open standard that uses the HTTP status `402 Payment Required` to ask for a payment. ChainPe uses x402 version 2. This page shows what's on the wire, using real responses from the demo API.

You don't need this to use the CLI or SDK. You do need it to [build your own client](/docs/developers/pay-without-sdk) or debug one.

## The flow

```text
Buyer                               Proxy                     Circle
  │  GET /forecast                    │                         │
  │ ────────────────────────────────► │                         │
  │  402, PAYMENT-REQUIRED            │                         │
  │ ◄──────────────────────────────── │                         │
  │  (signs a payment)                │                         │
  │  GET /forecast, PAYMENT-SIGNATURE │                         │
  │ ────────────────────────────────► │  settle                 │
  │                                   │ ──────────────────────► │
  │                                   │  success                │
  │                                   │ ◄────────────────────── │
  │                                   │  forward to your API    │
  │  200, PAYMENT-RESPONSE            │                         │
  │ ◄──────────────────────────────── │                         │
```

## 1. The 402

```bash
curl -i "https://chainpe-arc-demo-production.up.railway.app/forecast?city=Mumbai"
```

```http
HTTP/2 402
access-control-allow-origin: *
access-control-expose-headers: PAYMENT-REQUIRED,PAYMENT-RESPONSE,X-CHAINPE-AGENT-ID
cache-control: no-store
content-type: application/json; charset=utf-8
payment-required: eyJ4NDAyVmVyc2lvbiI6Mi...
x-chainpe-agent-id: 897796

{"error":"Payment required"}
```

`PAYMENT-REQUIRED` is base64-encoded JSON. Decoded:

```json
{
  "x402Version": 2,
  "error": "Payment required",
  "resource": {
    "url": "https://chainpe-arc-demo-production.up.railway.app/forecast?city=Mumbai",
    "description": "5-day temperature forecast for a city",
    "mimeType": ""
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:5042002",
      "amount": "10000",
      "asset": "0x3600000000000000000000000000000000000000",
      "payTo": "0x261f058496D81703c858DDFEd201834F0b5f2e73",
      "maxTimeoutSeconds": 300,
      "extra": { "name": "USDC", "version": "2", "paymentFlow": "upfront" }
    },
    {
      "scheme": "exact",
      "network": "eip155:5042002",
      "amount": "10000",
      "asset": "0x3600000000000000000000000000000000000000",
      "payTo": "0x261f058496D81703c858DDFEd201834F0b5f2e73",
      "maxTimeoutSeconds": 604900,
      "extra": {
        "name": "GatewayWalletBatched",
        "version": "1",
        "verifyingContract": "0x0077777d7eba4688bdef3e311b846f25870a19b9",
        "paymentFlow": "upfront"
      }
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `accepts` | The ways to pay. Pick one. A route under $0.01 lists only the Gateway option |
| `scheme` | Always `exact`: the buyer pays exactly `amount`. **It doesn't tell the rails apart** |
| `extra.name` | **This tells the rails apart.** `USDC` is a normal payment, `GatewayWalletBatched` is Gateway |
| `network` | The chain, in CAIP-2 format. `eip155:5042002` is Arc testnet |
| `amount` | Atomic USDC, with 6 decimals. `10000` is $0.01 |
| `asset` | The USDC ERC-20 contract on Arc |
| `payTo` | The seller's wallet |
| `maxTimeoutSeconds` | How long the signed payment stays valid |
| `extra` | The EIP-712 signing domain for the rail |

`X-CHAINPE-AGENT-ID` is the seller's ERC-8004 identity, so you can [rate it](/docs/concepts/identity-and-ratings) without looking it up.

## 2. The signed payment

The buyer sends the same request again with a `PAYMENT-SIGNATURE` header, which is base64-encoded JSON:

```json
{
  "x402Version": 2,
  "resource": { "url": "https://…/forecast?city=Mumbai", "description": "…", "mimeType": "" },
  "accepted": { "…": "the entry from accepts, copied unchanged" },
  "payload": {
    "signature": "0x…",
    "authorization": {
      "from": "0xBuyer",
      "to": "0xSeller",
      "value": "10000",
      "validAfter": "1793950000",
      "validBefore": "1793950900",
      "nonce": "0x…32 random bytes…"
    }
  }
}
```

On the `exact` rail, the signature is an EIP-3009 `TransferWithAuthorization`: a signed permission for one USDC transfer. The buyer holds no gas and sends no transaction, because Circle submits it. [Working code is here](/docs/developers/pay-without-sdk).

## 3. The result

**Success:** your API's own status and body, plus a `PAYMENT-RESPONSE` header. It's also base64-encoded JSON:

```json
{
  "success": true,
  "transaction": "0x11027eae…",
  "network": "eip155:5042002",
  "payer": "0xBuyer",
  "amount": "10000"
}
```

On Gateway, `transaction` holds Circle's transfer id, not a hash, because the on-chain batch lands later.

**Refused:** another `402`, with a reason in the body. Your API wasn't called.

```json
{ "error": "payment_failed", "reason": "insufficient_funds", "message": "insufficient_funds" }
```

All the reasons are in the [error reference](/docs/reference/errors).

A malformed `PAYMENT-SIGNATURE` isn't treated as a payment attempt. You get the plain `402` again.

## Discovery documents

Agents can read what you sell without paying. `chainpe doctor` generates the first two, and the proxy serves all three for free.

| Path | What it holds |
|---|---|
| `/.well-known/x402` | Every route, with price, method and rails |
| `/openapi.json` | OpenAPI 3.1, with parameters, response fields and `x-x402-price` |
| `/.well-known/agent.json` | The agent card your ERC-8004 identity points to |

Try the demo's:

```bash
curl https://chainpe-arc-demo-production.up.railway.app/.well-known/x402
```

```json
{
  "version": 1,
  "name": "ChainPe Weather Demo",
  "docsUrl": "https://chainpe-arc-demo-production.up.railway.app/openapi.json",
  "resources": [
    {
      "resource": "https://chainpe-arc-demo-production.up.railway.app/weather",
      "method": "GET",
      "path": "/weather",
      "description": "Current temperature, conditions, humidity and wind for a city",
      "price": "0.001",
      "amountAtomic": "1000",
      "network": "eip155:5042002",
      "payTo": "0x261f058496D81703c858DDFEd201834F0b5f2e73",
      "rails": ["gateway"]
    }
  ]
}
```

The format of `/.well-known/x402` is ChainPe's own, because Circle's docs don't define one.
